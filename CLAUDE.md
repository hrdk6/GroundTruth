# CLAUDE.md — working notes for this repo

Conventions, commands, and hard-won facts. `PROJECT_SPEC.md` is the source of
truth for *what* to build; this file is *how* to work in the repo.

## Ground rules (from PROJECT_SPEC.md §3, §13)

1. **Eval-first.** The harness came before the retrieval improvements. Do not
   ship a retrieval or prompt change without a before/after experiment.
2. **Never fabricate a number.** Every figure in the README, the dashboard, or
   a summary must trace to a file in `experiments/`. The README table is
   generated by `scripts/generate_results_table.py` — never hand-edited.
3. **Config-driven.** If a choice could change a result, it belongs in
   `configs/*.yaml`, not in a default argument.
4. **Work phase by phase.** Finish a phase, run the tests, update
   `PROGRESS.md` and `EXPERIMENTS.md`, commit, then stop and summarize.
   Do not start the next phase without approval.
5. **No RAG frameworks.** No LangChain, no LlamaIndex. The point is the
   internals.
6. **Record decisions.** A significant design choice gets an entry in
   `docs/ARCHITECTURE.md` under "Decisions" (context, choice, trade-off), and
   a known weakness gets one in `docs/LIMITATIONS.md`.
7. **Ask before spending.** Any step likely to cost more than ~$2 in API calls
   gets an estimate first.

## Commands

GNU make is not installed on the primary dev machine (Windows), so every target
exists twice: `Makefile` is the reference, `make.ps1` is a PowerShell shim.
**Changing one means changing the other.**

| Task | macOS/Linux/CI | Windows |
|---|---|---|
| Install deps | `make install` | `./make.ps1 install` |
| Start stack | `make up` | `./make.ps1 up` |
| Migrate | `make migrate` | `./make.ps1 migrate` |
| Tests | `make test` | `./make.ps1 test` |
| Lint + types + tests | `make check` | `./make.ps1 check` |
| Ingest | `make ingest` | `./make.ps1 ingest` |
| Evaluate | `make eval CONFIG=configs/x.yaml SPLIT=dev MODE=retrieval` | `./make.ps1 eval -Config configs/x.yaml -Split dev -Mode retrieval` |

Python commands run through `uv run` from `backend/`, which resolves the venv
automatically — there is no `activate` step.

## Environment facts

- **Python 3.12**, pinned in `backend/.python-version`. Not 3.13/3.14: torch and
  sentence-transformers wheels lag new releases, and the dev machine's system
  Python is 3.14.
- **Postgres 16 + pgvector** comes from the `pgvector/pgvector:pg16` image.
  There is no native Windows pgvector build worth the trouble; Docker is the
  supported path.
- **torch is pulled from the CPU-only index** (`[tool.uv.sources]` in
  `backend/pyproject.toml`). The default PyPI wheel bundles CUDA (~2.5GB) that
  this project never uses.
- **Windows Application Control blocks the venv's `.exe` console-script shims.**
  `uv run uvicorn ...` failed with `os error 4551`. Every command in the
  `Makefile` and `make.ps1` therefore uses `python -m <tool>`, which bypasses
  the shims. Keep it that way.
- **Async psycopg will not run on Windows' default event loop.** uvicorn passes
  an explicit `loop_factory` to `asyncio.run` (so setting a loop *policy* does
  nothing), and on win32 that factory is `ProactorEventLoop`, which psycopg
  rejects. `app/run.py` owns the `asyncio.run` call and forces
  `SelectorEventLoop`. Run the API natively with `make dev` / `./make.ps1 dev`,
  never bare `uvicorn`. Inside Docker (Linux) none of this applies.
- **Database connect timeout is 3s** (`CONNECT_TIMEOUT_SECONDS` in
  `app/core/db.py`). Without it, "Postgres isn't running" makes `/health` hang
  for ~4 minutes while psycopg retries every resolved address.
- The repo lives under **OneDrive** on the dev machine. `.venv/`,
  `node_modules/`, and `data/raw/` are gitignored, which also keeps them out of
  sync churn — do not move caches outside those paths.

## Anthropic API facts worth not rediscovering

These bit us once; they are encoded in `app/core/llm.py`.

- **`temperature` is rejected with a 400 on Claude 4.6+ models**, including
  `claude-sonnet-5` and `claude-opus-5`. Only Haiku 4.5 and older accept it.
  `LLMClient.complete` drops it for models that refuse it and logs at debug.
  Consequence: generation is *not* bit-reproducible from the API alone — the
  LLM cache is what makes an eval re-run deterministic.
- **The canonical cheap-model id is `claude-haiku-4-5`**, without a date suffix.
  `PROJECT_SPEC.md` names `claude-haiku-4-5-20251001`; that string is handled as
  an alias in the pricing table so either spelling costs the right amount.
- **The SDK is `anthropic` 1.x**, built on `httpx2` (not `httpx`). Do not pass
  an `httpx.Timeout` or `httpx.Client` to it.
- **Pricing lives in one table**, `PRICING_PER_MTOK` in `app/core/llm.py`
  (per MTok: Sonnet 5 $2/$10, Haiku 4.5 $1/$5). A wrong number there silently
  corrupts every cost figure in the README.

## Layout notes

- `app/core/settings.py` is *environment* (secrets, hosts). `app/core/pipeline.py`
  is *experiment* (chunker, k, models). Keep them apart or experiments stop
  being reproducible.
- `app/models/__init__.py` must import every ORM model. Alembic autogenerate
  diffs against `Base.metadata`; a model missing from that import is a table
  Alembic will propose dropping.
- Two DB engines share one URL: async for the API request path, sync for
  ingestion/evals/CLIs. Both are psycopg 3.
- Tests that need Postgres are marked `@pytest.mark.integration`;
  `make test-unit` skips them.

## Style

- Type hints everywhere; `ruff` and `mypy` (non-strict) must pass.
- Comments explain *why*, not *what*. A comment that restates the code is noise.
- Commit after each meaningful step, tests passing at every commit.
